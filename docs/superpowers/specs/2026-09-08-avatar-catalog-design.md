# 虚拟人角色目录设计

## 目标

以 7 个系统内置虚拟人作为唯一可选的系统角色，使运行时代码与视频生成 skill 中的角色身份、兼容服装和生成提示词保持一致。

支持的虚拟人如下：

- 小叶
- 程曦
- 青黛
- 小岚
- 瑶琴
- 云游
- 凌霜

“小洁”“小丽”“小蓉”等旧文本角色不再是受支持的系统角色。

## 现状问题

运行时虚拟人列表维护在 `src/video/preset-avatars.ts`，分镜 skill 又在多份 Markdown 中独立维护角色和服装。现有 skill 文档仍会向模型暴露以“小洁”为中心的旧角色和服装设定。

目前存在三个权威来源：

1. 运行时虚拟人的别名和素材 ID。
2. Skill 中的角色描述和样例。
3. Skill 中的服装预设及其提示词展开。

这些来源会在名称、身份、风格和服装兼容性上发生漂移。

## 设计

### 目录模型

在视频模块中引入结构化的虚拟人目录和服装目录，作为以下信息的唯一权威来源：

- 稳定的虚拟人 ID、别名、显示名称和人像素材 ID。
- 生成提示词所需的人设锚点和角色边界。
- 内容题材和视觉族群：`modern` 或 `hanfu`。
- 默认服装和允许使用的服装 ID。
- 服装名称、提示词片段、可兼容的视觉族群、可使用的虚拟人、场景标签。

每个虚拟人必须有一套有效的默认服装；每套服装必须至少能被一个虚拟人使用。

`preset-avatars.ts` 将由目录替代，或仅保留由目录派生的兼容导出。不得再保留手写的重复虚拟人数据。

### Skill 投影

分镜 skill 使用从目录生成或维护的精简索引，仅引用目录中的 ID 和别名。该索引不得再维护第二份人设、素材 ID、服装提示词展开或旧角色模板。

所有 skill 样例必须使用 7 个内置虚拟人之一。移除旧角色名、旧用户画像记录、固定身形指令，以及绑定“小洁”“小丽”“小蓉”的服装样例。

### 请求处理流程

1. 用户输入的别名先在虚拟人目录中解析。
2. 服务保存标准化角色元数据：`mode`、`presetAvatarId`、`presetAlias`、选择来源、角色提示词和服装 ID。
3. 用户未指定服装时，使用该虚拟人的默认服装。
4. 用户指定预设服装时，仅在该服装兼容目标虚拟人时接受。
5. 用户指定自定义服装时，先按虚拟人的视觉族群、人设边界、内容题材和安全约束校验，再生成服装提示词片段。
6. 保存分镜脚本时校验标准化组合。
7. 创建视频任务时再次校验已保存的组合，再解析虚拟人素材。

两处运行时校验可防止直接调用 API 时绕过 LLM 侧的指令约束。

### 旧角色与历史数据

不得将旧角色名自动映射到任一内置虚拟人。用户请求旧角色时，要求其从 7 个内置虚拟人中选择。

历史脚本保持可读、可生成，不进行批量重写。编辑主角色仍为旧文本角色的脚本时，必须在新版本中选择一个内置虚拟人及其兼容服装。

### 校验与错误处理

提供可复用的目录校验器，检查：

- 虚拟人 ID、别名和素材 ID 是否有效。
- `presetAlias` 是否与所选虚拟人一致。
- 服装是否存在且兼容目标虚拟人。
- 默认服装是否有效。
- 自定义服装是否兼容且安全。
- `none` 和 `user_portrait` 模式是否携带了预设虚拟人元数据。

校验失败时返回可恢复的明确提示。例如：“瑶琴仅支持古风服装，请选择先秦礼服或提供古风自定义服装。”系统不得静默替换为其他虚拟人或服装。

应用启动时执行目录完整性检查：

- 恰好存在这 7 个受支持的虚拟人。
- 每个虚拟人都有有效素材 ID 和默认服装。
- 每套服装至少可供一个虚拟人使用。
- 不存在重复别名。
- Skill 角色索引只引用已知的虚拟人和服装。

## 非目标

- 本次不新增虚拟人。
- 本次不批量改写历史脚本或已生成的分镜归档。
- 本次不移除用户上传人像功能。
- 本次不禁止自由描述自定义服装，而是对其做兼容性校验。
- 本次不新增单元测试或 skill 扫描测试。
